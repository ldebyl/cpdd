1mNAME0m
       cpdd - copy files with content-based deduplication

1mSYNOPSIS0m
       1mcpdd 22m[4mOPTIONS24m] 4mSOURCE24m... 4mDESTINATION0m

1mDESCRIPTION0m
       1mcpdd  22mis  a file copy utility that provides content-based deduplication
       by linking to identical files in a reference directory. It performs ef-
       ficient multi-stage matching: file size comparison,  optional  filename
       matching,  block-based hash rejection, and byte-by-byte content verifi-
       cation.

       When a reference directory is specified, files with  identical  content
       are linked (hard or symbolic) rather than copied, saving disk space and
       preserving storage efficiency.

1mOPTIONS0m
       1m-r22m, 1m--reference 4m22mDIR0m
              Use  4mDIR24m as reference directory for content-based linking. Files
              in 4mSOURCE24m that match content in 4mDIR24m will be  linked  instead  of
              copied. Defaults to hard links.

       1m-L22m, 1m--hard-link0m
              Create  hard links to reference files when content matches. This
              is the default when a reference directory is specified.

       1m-s22m, 1m--symbolic-link0m
              Create symbolic links to reference files when content matches.

       1m-R22m, 1m--recursive0m
              Copy directories recursively.

       1m-a22m, 1m--archive0m
              Archive mode: same as 1m-R --no-dereference --preserve=all22m, as  in
              1mcp22m(1).  Can  be  narrowed  with later options, e.g. 1m-a --no-pre-0m
              1mserve=ownership22m.  With  1m--skip-symlinks22m,  symbolic   links   are
              skipped instead of being copied as links.

       1m-n22m, 1m--no-clobber0m
              Never overwrite existing files.

       1m-i22m, 1m--interactive0m
              Prompt before overwriting existing files.

       1m-u22m, 1m--update0m
              Overwrite only if source is newer than destination.

       1m--dry-run0m
              Show what would be done without actually doing it.

       1m-N22m, 1m--only-new0m
              Only copy files that don't exist in reference directories. Files
              with identical content in the reference will be skipped entirely
              (not  copied  or linked). Requires at least one reference direc-
              tory (1m-r22m).

       1m-p     22mPreserve file attributes (equivalent  to  1m--preserve=mode,owner-0m
              1mship,timestamps22m).

       1m--preserve22m[=4mATTR_LIST24m]
              Preserve  specified  file  attributes. If no 4mATTR_LIST24m is given,
              preserves mode, ownership, and timestamps. Attributes accumulate
              across options, so  1m--preserve=mode  --preserve=atime  22mpreserves
              both. Available attributes:

              o   1mmode 22m- file permissions, including setuid/setgid/sticky bits

              o   1mownership  22m-  user  and  group  ownership. Changing a file's
                  owner requires root; when  it  isn't  permitted,  the  group
                  alone  is set if possible. That fallback is silent when own-
                  ership is requested implicitly (by 1m-p22m, 1m-a22m, a bare 1m--preserve0m
                  or 1mall22m) and a reported failure when 1mownership 22mis  named  ex-
                  plicitly,  as  in  1mcp22m(1). Either way, setuid and setgid bits
                  are dropped from a copy that did not get the matching  owner
                  or group.

              o   1matime 22m- access time

              o   1mmtime 22m- modification time

              o   1mtimestamps 22m- atime and mtime

              o   1mall 22m- all of the above

              Timestamps  are  copied with full nanosecond precision. A direc-
              tory's attributes are  applied  after  its  contents  have  been
              copied,  so  its  mtime is not reset by the files created inside
              it. With 1m--no-dereference22m, ownership and timestamps are  applied
              to  copied  symbolic links themselves. Nothing is preserved on a
              1m--dry-run22m. Hard-linked reference  matches  share  the  reference
              file's  inode,  so  they always carry the reference's attributes
              and are never modified.

              1mctime 22m(inode change time) and birth time  cannot  be  preserved:
              the kernel sets them, and offers no call to set them to an arbi-
              trary value. Every copy's ctime is the time it was written.

       1m--no-preserve22m=4mATTR_LIST0m
              Don't preserve the specified attributes, using the same names as
              1m--preserve22m. Options are applied left to right, so 1m--preserve=all0m
              1m--no-preserve=atime 22mpreserves everything except atime.

       1m--stats0m
              Display statistics after the copy operation, including number of
              files copied, linked, and skipped.

       1m--block-size 4m22mSIZE0m
              I/O  block  size  for  file operations. SIZE can be specified in
              bytes or with suffix K, M, G (e.g., 64K, 1M). Default:  auto-de-
              tect from filesystem.

       1m-m22m, 1m--match-name0m
              Match on filename in addition to size. When enabled, only refer-
              ence  files  with  the  same basename as the source file will be
              considered for matching. Size matching is always performed.

       1m--match-mtime0m
              Match on modification time in addition to size:  only  reference
              files  with  the  same  mtime as the source file are considered.
              Times are compared in whole seconds, since sub-second  precision
              is  often  lost when files are copied. Only useful if the refer-
              ence copies kept their original mtimes (e.g. made with 1m-a22m, 1m-p 22mor
              1mrsync -a22m).

       1m--no-verify0m
              Skip content comparison and accept matches based solely on  size
              plus  filename  and/or  mtime. Requires 1m--match-name 22mor 1m--match-0m
              1mmtime22m. Use with caution as this may create links to  files  with
              different  content  if their metadata happens to agree. 1m--match-0m
              1mmtime --no-verify 22mwithout 1m--match-name  22mis  particularly  risky:
              any  reference  file with the same size and mtime matches, what-
              ever its name. With 1m--cache-file22m, matches are made against  ref-
              erence  metadata  as  it was when cached; use 1m--cache-ttl 22mif the
              reference may change between runs.

       1m--quick-match0m
              Same as 1m--match-name --match-mtime --no-verify22m: treat  a  refer-
              ence  file with the same name, size and mtime as identical with-
              out reading either file, like 1mrsync22m(1)'s  default  quick  check.
              Much faster when most of the source already exists in the refer-
              ence, at the cost of trusting metadata over content.

       1m--no-dereference0m
              Do  not  follow  symbolic  links. When this option is specified,
              symbolic links are copied as symbolic links rather than  copying
              the files they point to. Duplicate detection is skipped for sym-
              bolic  links.  Without this option (default), symbolic links are
              dereferenced and their targets are  copied.  Mutually  exclusive
              with 1m--skip-symlinks22m.

       1m--prune-empty-dirs0m
              Don't leave empty directories in the destination. A directory is
              pruned  when  nothing  ends  up in it, either directly or in any
              subdirectory: this covers directories that  were  empty  in  the
              source,  and also ones whose files were all skipped, e.g. as du-
              plicates with 1m-N 22mor as already-processed  with  1m--log-processed22m.
              Only  directories  this run creates are pruned. Directories that
              already existed are left alone, and the  destination  itself  is
              never  removed.  With  1m--dry-run  -v22m,  directories that would be
              pruned are listed as 1m[PRUNE]22m. Equivalent to 1mrsync22m(1)'s  1m--prune-0m
              1mempty-dirs22m.

       1m--skip-symlinks0m
              Skip  symbolic links entirely. Symbolic links are neither copied
              nor dereferenced - they are simply ignored. Useful  for  copying
              only  regular  files  or  when copying to filesystems that don't
              support symbolic links. Mutually  exclusive  with  1m--no-derefer-0m
              1mence22m.

       1m--min-size 4m22mSIZE0m
              Minimum file size in bytes for duplicate matching. Files smaller
              than 4mSIZE24m are always copied normally without checking for dupli-
              cates. Default: 1 (skip empty files).

       1m--log-processed 4m22mFILE0m
              Resume-aware  processed-files log. On startup, if 4mFILE24m exists it
              is loaded as a skip-set: any source whose path, size  and  mtime
              all match a recorded entry is skipped before reference matching,
              so  a re-run with 1m--only-new 22mdoes not need to re-hash references
              or re-compare every source. Then 4mFILE24m is opened for append and a
              tab-separated record (4mpath24m, 4msize24m, 4mmtime24m,  4mdecision24m)  is  written
              for  every  source  that  reaches  a  final disposition (copied,
              linked, or skipped). Failures are never logged, so they get  re-
              tried  on the next run. The log is line-buffered and flushed af-
              ter every record so an interrupted run leaves a consistent  file
              on  disk;  pointing the next invocation at the same 4mFILE24m resumes
              where it left off. A source whose  size  or  mtime  has  changed
              since  being  logged  is  treated as new and processed normally.
              Paths containing backslash, tab or newline are escaped as  1m\\\\22m,
              1m\\t  22mand  1m\\n  22mrespectively. Decisions emitted: 1mCOPY22m, 1mLINK-HARD22m,
              1mLINK-SOFT22m, 1mLINK-SRC-HARD22m, 1mLINK-SRC-SOFT22m,  1mSKIP-DUP  22m(matched  in
              reference  under  1m--only-new22m),  1mSKIP-EXIST  22m(destination already
              present under 1m--no-clobber  22mor  1m--update22m),  1mSKIP-SYMLINK22m,  1mSKIP-0m
              1mSAMEFILE  22m(source and destination are already the same file; see
              1mSAME-FILE PROTECTION22m).

       1m--cache-file 4m22mFILE0m
              Persist the scanned reference index (paths, sizes and any  block
              hashes  built  up while matching) to 4mFILE24m, and reuse it on later
              runs against the same reference directories instead  of  rescan-
              ning  them.  Each  1m-r  22mdirectory is tracked independently by its
              canonical (1mrealpath22m(3)) form, so a directory  not  part  of  the
              current  run  is  simply  not used for matching, and a directory
              reused from 4mFILE24m is only ever  matched  against  files  actually
              within it: nothing found via the cache can be outside the set of
              1m-r 22mdirectories given on this invocation, whatever else 4mFILE24m hap-
              pens  to  still hold from an earlier run. A directory present in
              4mFILE24m but not requested this run is dropped  once  4mFILE24m  is  next
              written,  rather  than kept. 4mFILE24m is written directly (no atomic
              rename): it is written to periodically during a long run as well
              as once at the end, and a crash or interruption at  worst  loses
              the  most  recent partial checkpoint, never something 4mFILE24m can't
              recover from on its own -- the  cache  is  entirely  regenerable
              from  the  reference directories, so a missing, truncated or in-
              compatible 4mFILE24m is silently treated as absent and  rescanned  in
              full, never an error.

       1m--cache-ttl 4m22mSECONDS0m
              Treat  a  reference  directory's entry in 1m--cache-file 22mas stale,
              and rescan it, once more than 4mSECONDS24m have passed since  it  was
              last scanned (tracked per directory, not by 4mFILE24m's own modifica-
              tion  time, so directories cached at different times each expire
              on their own schedule rather than all sharing whichever one  was
              written most recently). Default: no expiry -- a cached directory
              is  reused until it is dropped (not requested on some later run)
              or 4mFILE24m is removed. Requires 1m--cache-file22m.

       1m-h22m, 1m--human-readable0m
              Show file sizes in human-readable format (K, M, G) in statistics
              and verbose output.

       1m-v22m, 1m--verbose0m
              Verbose output showing files being processed and their  disposi-
              tion. Can be specified multiple times to increase verbosity:

              o   1m-v 22m- Show basic operation progress (level 1)

              o   1m-vv 22m- Show detailed file operations (level 2)

              o   1m-vvv 22m- Show debug information (level 3)

       1m--help 22mDisplay help message and exit.

1mEXAMPLES0m
       1mBasic file copy:0m
              cpdd file1.txt file2.txt /dest/

       1mRecursive directory copy:0m
              cpdd -R src1/ src2/ /dest/

       1mCopy with hard link deduplication:0m
              cpdd -r /reference/ -R -v source/ /dest/

       1mCopy with symbolic link deduplication:0m
              cpdd -r /reference/ -s --stats source/ /dest/

       1mInteractive copy preserving attributes:0m
              cpdd -i -p -R src/ dest/

       1mCopy only new files not in reference:0m
              cpdd -r /reference/ -N -R source/ /dest/

       1mResumable copy across runs:0m
              cpdd -R --log-processed run.log src/ /dest/
              cpdd -R --log-processed run.log src/ /dest/
              The  second invocation re-uses the same log: it reads any exist-
              ing entries as a skip-set and then appends new ones. This  works
              even  for  files  dropped  by  1m--only-new 22mthat leave no trace in
              4m/dest/24m.

       1mRepeated runs against the same large reference set:0m
              cpdd -R -r /reference/ --cache-file ref.cache --cache-ttl  86400
              source/ /dest/
              The  first  run  scans 4m/reference/24m in full and writes 4mref.cache24m.
              Later runs against the same 1m-r 22mreuse it instead  of  rescanning,
              as long as it is less than a day (86400s) old; add, drop or swap
              1m-r  22mdirectories between runs freely; each is tracked, cached and
              expired independently.

1mFILE MATCHING ALGORITHM0m
       1mcpdd 22muses a multi-stage matching process for efficient deduplication:

       1.  1mSize comparison 22m- Files must have identical size to  be  considered
           for matching.

       2.  1mFilename and mtime comparison (optional) 22m- When 1m--match-name 22mis en-
           abled,  only  files  with  matching  basenames are considered. When
           1m--match-mtime 22mis enabled, only files  with  the  same  modification
           time (whole seconds) are considered. These checks use only metadata
           already gathered by the scan, so they cost no extra I/O.

       3.  1mBlock-based  hash comparison 22m- Cached block hashes provide fast re-
           jection of non-matching files. This  only  ever  rejects  a  match,
           never  confirms  one  (step  4 always still runs before anything is
           linked), and it only helps once a source file  has  more  than  one
           same-size  reference  candidate  to  compare  against:  each source
           file's own hash chain always starts empty, so the very first candi-
           date it checks is never fast-rejected regardless of  what  1m--cache-0m
           1mfile  22mcarries  over.  Reference  trees  with  many same-sized files
           (thumbnails, sequential exports, RAW+JPEG pairs) benefit the  most;
           a  reference tree with few or no same-size collisions gets no bene-
           fit from this stage either way, cached or not.

       4.  1mByte-by-byte comparison 22m- Final  verification  ensures  content  is
           truly identical before linking (skipped if 1m--no-verify 22mis used).

           This approach minimizes expensive I/O operations while guaranteeing
           correctness.  The  1m--no-verify 22moption (and 1m--quick-match22m, which im-
           plies it) trades accuracy for speed by skipping steps 3 and  4  en-
           tirely, so neither file is read.

1mEXIT STATUS0m
       1mcpdd 22mexits with status 0 on success, 1 on error.

1mFILES0m
       No configuration files are used.

1mNOTES0m
       Hard links can only be created between files on the same filesystem. If
       hard linking fails, 1mcpdd 22mwill fall back to copying the file normally.

       Symbolic  links in reference directories or created with 1m-s 22mcontain the
       path to the target file and can span filesystems, but may break if  the
       reference directory is moved or deleted.

       When copying symbolic links in the source:

       o   By  default,  symbolic  links are dereferenced (followed) and their
           target files are copied.

       o   With 1m--no-dereference22m, symbolic links are copied as symbolic  links
           (including broken ones).

       o   With  1m--skip-symlinks22m,  symbolic  links  are  skipped entirely (not
           copied at all).

       o   Broken symbolic links are skipped with a warning when dereferencing
           (default mode).

1mSAME-FILE PROTECTION0m
       A regular copy never writes into an existing destination in place.  The
       destination  path is unlinked first, and a brand new file is created to
       hold the source's content.

       This matters because a destination path  can  share  its  content  with
       something  else  entirely,  without  that  being  obvious from the path
       alone: it can be a hard link - to the source itself, typically left  by
       an earlier 1mcpdd 22mrun's reference-match linking (1m-L22m), or to any other un-
       related  file  - or a symlink to some other target. Opening such a path
       directly and truncating it, as a naive overwrite would, rewrites  what-
       ever  it currently shares content with, silently corrupting a file that
       has nothing to do with the copy. Unlinking the destination  name  first
       removes  only that one name; it can never affect other names that share
       the same underlying data, so the file created afterward is  always  new
       and independent.

       As a special case, if the destination is already the exact same file as
       the  source (matched by device and inode), the copy is skipped entirely
       (logged as 1mSKIP-SAMEFILE22m) rather than unlinked and recreated: the  con-
       tent  is  already identical, and skipping preserves whatever space that
       hard link was already saving instead of duplicating it.

       One consequence: unlike a plain in-place overwrite, an existing  desti-
       nation's own permissions, ownership and timestamps do not survive being
       overwritten  -  the  new file gets the source's mode (via the umask) as
       usual for a newly created file, the same as when  the  destination  did
       not exist beforehand. Use 1m-p22m/1m--preserve 22mif the destination's attributes
       should  instead  be  made to match the source's explicitly. This trades
       away a property some tools' in-place overwrite deliberately keeps  (see
       1mcp22m(1)'s 1m--remove-destination22m, which is the opposite of 1mcp22m's own default
       for  exactly  this  reason) in exchange for the corruption this section
       describes never being possible.

       This check does not apply to hard or symbolic linking itself:  creating
       a  new  link  already removes any existing destination file name first,
       and is always safe in the same way.
